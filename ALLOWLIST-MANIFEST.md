# Publication Allowlist & Audit Manifest

This manifest documents the provenance, classification, and safety audit status of all exported artifacts in the history-free **Tenderpad Portfolio Showcase**.

## Audit & Redaction Principles

1. **Offline-by-default & Offline-First:** No live scrapers, no remote credentials, and no external API dependencies are included or exposed.
2. **Real open data, attributed:** `tests/fixtures/kbo/*.csv` are unmodified KBO Open Data records for enterprise `0404.484.060` (snapshot 24-06-2026, extract 401, FPS Economy), reused under the KBO licence with source and update date stated in `FIXTURES.md`. `tests/fixtures/bda/brugge-notice.xml` is a real published BOSA notice (Stad Brugge, CPV 72210000) with contact email, telephone and telefax removed, declared in the file; `tests/fixtures/bda/notice.xml` is the product's synthetic UBL fixture with a fictional authority. `web/example.js` remains a labelled fictional illustration and is not derived from either source.
3. **Reference Data Provenance:**
   - `cpv.json` & `nuts-bel.json`: Standard European Union CPV 2008 and Belgian NUTS level 3 codelists from OP-TED eForms-SDK release 1.15.1.
   - `matcher_tables.json`: Taxonomy crosswalk mapping CPV divisions to NACE prefixes, warning triggers, and baseline term weights.
   - `text_tfidf.json`: 60,000 character 3–5 gram IDF weights built over 3,441 tender notices; provenance recorded in the file.
   - `winner_profile.json`: Smoothed NACE-CPV log-odds built from 9,002 award-history rows, 2017–2021; provenance recorded in the file.
4. **Ranking Fidelity:** The mathematical matching models (`activity_match`, `region_match`, `value_match`, `history_match`, `deadline_match`, `recognition_match`, and candidate ranking) are preserved exactly as implemented in the private prototype, rather than replaced by a toy mock.

## Allowlisted File Manifest

The authoritative file list is machine-checked, not hand-maintained:

| File | Meaning |
|---|---|
| `export/published.txt` | Generated by the publish script: every published path with its sha256, plus the source commit. |
| `scripts/publish/published-paths.txt` (in the product repository) | The product paths that are published, one per line. |
| `showcase/` (in the product repository) | The overlay files, each stored at the path it is published under. |

`tests/safety_check.cjs` runs the listing check on every gate, in both
directions: a file present but unlisted fails `just ci`, and a listed file that
is missing fails too. A directory catch-all would defeat that, so none is used.

No directory catch-alls are used: each path is listed individually, which is what
made the previous table unable to fail.
